# Bilibili 收藏夹失效视频信息还原

[**简体中文**](./README.zh-CN.md) | [繁體中文](./README.zh-TW.md)

还原 bilibili 网页版收藏夹中失效（已删除 / UP 自删 / 政策下架）视频的原始封面、标题与作者信息。同时检测并展示 bilibili 服务端层面已经丢弃、不在常规接口返回的条目，并附第三方归档站快照链接。

bilibili 网页版收藏夹接口对失效条目仅返回固定占位封面与「已失效视频」文字。本脚本调用 bilibili Android 客户端使用的接口（含正确签名），从服务端取回失效前的元数据快照并替换页面 DOM。此外提供本地备份功能，可在条目仍然有效时预先留存封面与信息，日后失效时直接以本地数据还原，不依赖任何远端是否仍保有该条目。

## 功能

- 还原失效条目的原始封面、标题、作者、播放数与弹幕数，并以删除线与灰化标记区分已还原的卡片
- 页内悬浮按钮：可拖动定位，点击展开二级菜单，涵盖脚本的全部命令
- 检测 bilibili 服务端静默丢弃的条目（API 实际返回数小于声明总数），列出对应 av 号并附 biliplus 与 jijidown 两个第三方归档站的快照链接
- 在卡片三点菜单中注入复制、还原与重试相关的操作
- 对确已删除、反复重试仍无结果的条目，支持逐条或整页停止重试，避免每次进入收藏夹重跑同一轮采样
- 备份当前收藏夹的元数据与封面图本体至浏览器 IndexedDB，可导出为 ZIP 文件自行保管，也可将该文件重新导入以合并回 IndexedDB 或迁移至另一域名
- 提供 TV 端二维码登录与手动粘贴 `access_key` 两种登录模式
- 元数据本地缓存（GM storage），减少对 bilibili API 的重复请求
- 页内设置面板：扫描页数上限、后台重试节奏、缓存有效期、请求超时、备份并发等 31 项参数可调，第三方存档源可单独关闭，修改即时生效

## 首次使用

1. 安装脚本后，打开任意收藏夹页面，例如 `https://space.bilibili.com/{UID}/favlist?fid={收藏夹 ID}`。
2. 点击页面右下角的悬浮按钮，选择 **账号与登录 → 登录（TV 端二维码）**。
3. 使用 bilibili 手机客户端扫描页面上显示的二维码并在手机端确认登录。仅 bilibili 官方客户端可用，微信扫码或网页扫码无效。
4. 登录成功后 `access_key` 写入 GM storage，有效期约 30 天。刷新页面后，失效条目应自动恢复原始封面与标题。

若 TV 模式下仍有条目无法取回原始元数据，可改用 **账号与登录 → 登录（手动输入凭据）**，粘贴一份由 Android 主端应用签发的 `access_key`。

未登录或已执行注销时，脚本不再发起任何还原相关的网络请求，仅以本地缓存与备份还原可覆盖的条目。

## 页内操作入口

收藏夹页面右下角常驻一枚圆形悬浮按钮，为脚本的主要入口。按住即可拖动到顺手的位置，该位置会被记住；点击则展开菜单。

菜单分为两级：一级为五个功能分类，点击进入二级后，最上方一行为「返回」。按 Esc 键逐级返回，点击菜单以外的区域关闭。部分条目右侧以浅色小字显示当前状态，例如登录模式、已停止重试的条目数，于菜单展开时即时计算。

| 分类 | 条目 |
| ---- | ---- |
| 账号与登录 | 登录（TV 端二维码）、登录（手动输入凭据）、查看登录状态、注销 |
| 扫描与修复 | 立即重新扫描并修复、扫描静默丢弃的条目 |
| 重试控制 | 本页全部停止重试、清除所有「停止重试」标记 |
| 备份 | 备份当前收藏夹、管理备份、导入备份文件 |
| 维护与调试 | 开关调试日志、清除所有缓存并刷新页面 |
| 设置 | 直达项，无二级菜单；打开设置面板 |

同一组命令亦可在浏览器扩展图标的脚本菜单中找到，前缀为 `fav-fix：`，两处行为完全一致。此外，收藏夹卡片右上角的三点菜单中会注入复制 AV / BV 号、复制完整信息、查看原始封面、在 biliplus 查看、清缓存并重抓，以及停止或恢复该条目重试等操作，按卡片当前状态显示。

## 停止无谓的重试

bilibili 的 Android 端收藏接口并不稳定，同一收藏夹的失效条目在每次遍历中会随机遗漏一部分。脚本据此对未能立即还原的条目启动后台重复采样：连续七轮无新增即判定为无法取回并停止，全程约四分钟。对于确实已被永久删除的条目，该过程不会有任何结果，却会在每次进入该收藏夹时重新执行一遍。

因此脚本提供两层抑制机制：使用者显式停止的记录永久有效，直至显式恢复；后台采样自行放弃时写入的记录有效期为 7 天，到期后该条目恢复正常重试。

操作方式：

- **封面按钮**：仍在重试的卡片，其封面正中央有一枚圆形按钮，按当前状态显示停止图标（方块）或恢复图标（循环箭头），点击即执行。封面左上角的小标签仅指示状态，不可点击。
- **卡片三点菜单**：提供「停止重试」与「恢复重试」，按卡片当前状态互斥显示。
- **本页全部停止重试**（菜单 → 重试控制）：一次停止当前页面上全部仍在重试的条目。
- **清除所有「停止重试」标记**（菜单 → 重试控制）：清空全部停止记录。该记录以 av 号为键、不区分收藏夹，因此此项的范围是所有收藏夹，而非当前页面。

停止的对象是网络重试，不影响本地数据：已备份的条目仍会照常以本地备份还原，停止记录亦不受「清除所有缓存」影响。

## 备份收藏夹到本地

还原流程属于事后补救，能否取回不由脚本决定。备份功能与之相反，用于在条目仍然有效时预先留存。

选择 **菜单 → 备份 → 备份当前收藏夹**，脚本将逐页遍历当前收藏夹，把标题、简介、UP 主、分区、时长、投稿与收藏时间等元数据，以及封面图的图片本体，写入浏览器的 IndexedDB。该收藏夹中的条目日后失效时，备份将作为优先级最高的数据源参与还原：即使 bilibili CDN 已清除封面图文件，脚本也会改用备份中的图片本体填充卡片封面。

备份可重复执行，封面地址未变化的条目仅更新元数据、不重复下载图片。任何清除缓存的操作均不会删除备份数据。

选择 **菜单 → 备份 → 管理备份** 可打开页内面板，浏览、搜索、按收藏夹过滤、导出或删除已存备份。面板底部的「导出筛选结果」将当前筛选结果打包为一个 ZIP 文件并交由浏览器下载，内含 `manifest.json`、`items.json` 与 `covers/` 目录下的封面原始字节，可自行长期保管。

若需要将此前导出的 ZIP 文件重新导入，可在备份管理面板底部点击「导入备份文件」，或经悬浮按钮菜单的 **备份 → 导入备份文件**、Tampermonkey 扩展菜单的 `fav-fix：导入备份文件` 打开文件选择对话框。导入按条目合并到 IndexedDB 中的既有备份：备份时间较新者优先，所属收藏夹取并集，已存的封面不会被空值覆盖，因此重复导入同一份文件不会产生变化。文件解压后以其他工具重新压缩仍可正常导入。该文件同时可导入到另一个域名（`space.bilibili.com` 与 `www.bilibili.com`）下运行的脚本，是在两者独立数据库之间迁移备份的方式。

## 设置

悬浮按钮菜单最下方的 **设置** 打开页内设置面板，Tampermonkey 扩展菜单中的 `fav-fix：设置` 与之等效。面板分为扫描与修复、后台重试、缓存与标记、网络与数据源、备份、界面与调试六个分页，共 31 项参数：修复扫描的页数上限、后台重试的放弃条件与间隔梯度、两档缓存有效期、各类请求超时与数据源熔断条件、备份的翻页间隔与封面下载并发数、备份管理面板的每页条数等，均可按需调整；biliplus 与 jijidown 两个第三方存档源亦可单独关闭，关闭后脚本不再向对应站点发送任何请求。

面板没有「保存」按钮：数值在失去焦点或按下回车时提交，开关在点击时提交，提交后立即生效，无需刷新页面。超出范围的输入会被拒绝并在字段下方说明原因，输入内容保留在原处以便修改。已修改的项目在标题旁标注「已修改」并提供单项重置，面板底部另有按分组或全部恢复默认值的按钮。

## 已知限制

- 仅支持本人收藏夹或公开收藏夹。私密收藏夹由 API 鉴权限制无法读取。
- 脚本返回的「原始封面」托管于 bilibili CDN，若 bilibili 在服务端清除该资源文件，脚本无法恢复，此前已执行备份的条目除外。
- 每页 20 条，默认最多翻阅 50 页（约 1000 条），可在设置面板中调整。
- 第三方归档源（biliplus、jijidown）的可用性与命中率不在脚本控制范围内。
- 若 bilibili 接口签名密钥被官方轮换（错误码 `-3` / `-101` / `-663`），需等待新版本发布。
- 「停止重试」记录、悬浮按钮位置与设置面板中的全部参数不在多个标签页之间实时同步，在一处修改后，其他已打开的标签页需刷新才会反映。
- 备份数据库受浏览器同源策略约束，`space.bilibili.com` 与 `www.bilibili.com` 各自持有独立的一份，需分别备份；不过导出的 ZIP 文件可重新导入到任一域名，是两者之间迁移备份的支持方式。备份亦不随浏览器配置文件同步，更换浏览器或清除站点数据后不再存在；如需长期保管，请使用导出功能。
